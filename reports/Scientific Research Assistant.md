## 2. Chunk Post-processing

A dedicated post-processing module was implemented:

`src/scientific_research_assistant/chunking/postprocess.py`

The module contains approximately 197 lines of code and is designed to improve the quality of chunks generated by the recursive and semantic splitting strategies.

The main objectives include:

- Removing references and irrelevant fragments.
    
- Filtering extraction noise.
    
- Handling fragmented text.
    
- Preserving meaningful scientific content.
    
- Avoiding unnecessary removal of short but informative chunks.
    

The implementation follows a conservative cleaning approach because scientific documents frequently contain short equations, definitions, and technical statements that should not be discarded merely because of their length.

## 3. Retriever Implementation

A dedicated retrieval module was implemented:

`src/scientific_research_assistant/retrieval/retriever.py`

The Retriever connects the embedding model, Qdrant vector database, and LangChain Document interface.

### Main capabilities

1. Supports two retrieval strategies:
    
    - Recursive
        
    - Semantic
        
2. Supports metadata filtering:
    
    - `paper_id`
        
    - `category`
        
3. Supports retrieval from multiple research domains.
    
4. Generates query embeddings using the existing embedding provider.
    
5. Retrieves relevant chunks from Qdrant.
    
6. Converts retrieved results into LangChain Documents.
    
7. Preserves document metadata and retrieval scores.
    

For multi-domain queries, retrieval is performed separately for each selected category. The results are then deduplicated and ranked.

### Initial retrieval tests

The following queries were tested:

|Query|Expected Paper|Observed Result|
|---|---|---|
|ResNet-related question|ResNet|ResNet retrieved|
|BERT-related question|BERT|BERT retrieved|
|Adam optimizer question|Adam|Adam retrieved|

Initial retrieval scores were:

- ResNet: 0.8482
    
- BERT: 0.8936
    
- Adam: 0.8422
    

These results indicate that the retrieval pipeline is operational. However, similarity scores alone do not establish retrieval quality. A dedicated evaluation dataset and ranking metrics are still required.

## 5. Prompt Engineering

A dedicated prompt module was created:

`src/scientific_research_assistant/generation/prompts.py`

The system prompt establishes strict grounding requirements.

The model is instructed to:

- Answer using only the retrieved scientific context.
    
- Avoid unsupported assumptions and external knowledge.
    
- Include source identifiers in factual claims.
    
- Never invent source IDs or page numbers.
    
- Explicitly acknowledge insufficient evidence.
    
- Explain conflicting evidence when multiple sources disagree.
    
- Respond in the same language as the user's question.
    

The citation format currently uses source identifiers such as:

`[S1]`, `[S2]`

This separates source identification during generation from the actual paper metadata displayed to the user.

Automated citation validation is not yet implemented.

## 7. RAG Answer Generation

The main RAG implementation is located in:

`src/scientific_research_assistant/generation/answer.py`

The file currently contains approximately 402 lines.

The `RAGChain` class integrates the following components:

1. DomainRouter
    
2. Retriever
    
3. LLM
    
4. RAG Prompt
    
5. Context formatting
    
6. Answer generation
    
7. Source presentation
    

### Execution workflow

The current execution sequence is:

1. Receive the user's question.
    
2. Determine the relevant research domains.
    
3. Check whether the question belongs to the supported domains.
    
4. Retrieve relevant chunks from Qdrant.
    
5. Format the retrieved documents as scientific context.
    
6. Construct the LLM prompt.
    
7. Generate the answer.
    
8. Display the answer and retrieved sources.
    

The implementation also includes resource cleanup through the Retriever's `close()` method.

Current interface features include:

- Markdown formatting.
    
- Generated answer panel.
    
- Retrieved source table.

The implementation supports both string-based and list-based text content in streamed chunks.

This provides a more interactive interface than waiting for the complete answer before displaying anything.

## 9. End-to-End Testing

### Test 1 — Single-domain scientific question

**Question:**

How does ResNet solve the degradation problem?

**Results:**

- Routing: Computer Vision + Machine Learning
    
- Retrieved chunks: 10
    
- Unique sources: 6
    
- Generation time: 14.46 seconds

An important scientific distinction was also observed: the degradation problem discussed in ResNet is not simply the vanishing-gradient problem. It concerns optimization difficulties in increasingly deep plain networks.

The system successfully routed the question and retrieved relevant documents from both domains.

However, the generated answer was empty.

This is a known issue requiring investigation. The actual streamed chunk contents and response metadata must be inspected before identifying the root cause.

- Retrieved chunks: 5
    
- Unique sources: 2
    
- Generation time: 15.64 seconds
    
- Answer generation: Successful
    

The model generated an answer based on the retrieved Adam paper and appropriately acknowledged that the available context did not contain the exact update equations and pseudocode.

## 12. Known Issues and Limitations

The following issues were identified during testing:

### 12.1 Empty Streaming Response

The cross-paper comparison test returned an empty answer despite successful routing and retrieval.

The next debugging step is to inspect:

- `chunk.content`
    
- `chunk.response_metadata`
    
- `chunk.additional_kwargs`
    
- Finish reason
    
- Final accumulated answer
    

The implementation should also detect empty generations and return an explicit error instead of displaying a blank answer.

### 12.2 Retrieval Noise

Some retrieved chunks are not directly relevant to the question.

For example, Dropout chunks appeared during the ResNet degradation query.

Retrieval quality should be measured systematically before modifying chunk sizes, similarity thresholds, or ranking logic.

### 12.3 Citation Validation

The model is instructed to cite sources, but the generated citations are not yet independently validated.

A validation stage should check whether every cited source identifier exists in the retrieved source list.

### 12.4 Evaluation

The current tests demonstrate that the system works in several scenarios, but they do not constitute a comprehensive evaluation.

A labeled benchmark is still required.
